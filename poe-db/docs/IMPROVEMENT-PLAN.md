# План улучшения окружения (23.11.2026)

Цель: перейти от «справочника и аудита чужих PoB» к полноценному билдостроению с нуля. Три сессии с непересекающимися зонами файлов.

| Сессия | Тема | Зависимости | Можно параллельно |
|---|---|---|---|
| 1 | Движок PoB: запуск, редактирование билда, share code, git | — | с сессией 2 |
| 2 | Данные и дерево: граф пассивок, прокачка, изменения 3.30, мета | — | с сессией 1 |
| 3 | Анализ: Node Power, ранжирование улучшений, проверка против боссов, оценка модели | после 1 (желательно после 2) | — |

Общие правила для всех сессий:
- Начинать с `node poe-db/scripts/agent.mjs bootstrap`, соблюдать `AGENTS.md`.
- Перед изменениями: `agent.mjs backup before-<тема>`.
- `scripts/agent.mjs` общий: добавлять команды отдельным модулем и минимальной регистрацией в диспетчере, не переписывать чужие разделы.
- В `docs/HANDOFF.md` дописывать только свой короткий пункт; в этом файле отмечать статус своей сессии.
- Не трогать `builds/main` (кроме тестовых билдов в отдельном id), `experiments/craft-lab`, глобальные настройки.
- Приёмка: `node --test` из `poe-db` зелёный, `doctor --deep` проходит, новые команды покрыты тестами и описаны в `ENVIRONMENT.md`.

Отложено (после трёх сессий): оценка рарок через trade API, интеграция craft-lab в общий CLI, прочие Timeless-базы по требованию.

## Промпт сессии 1 — движок PoB и редактирование билда

```
Проект: локальное окружение для билдостроения PoE 1 3.30 (папка "<project>"). Прочитай AGENTS.md и poe-db/docs/IMPROVEMENT-PLAN.md (общие правила), выполни bootstrap. Твоя зона: poe-db/scripts/pob.mjs, pob-worker.lua, pob-runtime.lua, pob-host.ps1, setup-pob.mjs, environment.mjs (doctor), раздел pob в agent.mjs, тесты PoB. Данные/SQLite и граф дерева делает другая сессия — их не трогай.

Задачи по порядку:
1. Починить запуск движка: pob.mjs:131 жёстко вызывает pwsh.exe, а на машине только Windows PowerShell 5.1 -> `pob control` падает с ENOENT, 2 из 58 тестов красные. Сделай поиск хоста (pwsh.exe, затем powershell.exe), проверь совместимость pob-host.ps1 с 5.1 (или адаптируй), сообщай понятную ошибку. Обычный `doctor` должен проверять запускаемость движка, а не только файлы (сейчас он пишет ready:true при сломанном PoB). Не устанавливай ПО в систему без моего подтверждения.
2. Расширить `--changes` (и сохранять результат через --save-xml):
   - tree: allocate/deallocate узлов по id или имени, выбор masteries, сокеты джевелов, восхождение и bloodline с проверкой бюджета и связности пути;
   - skills: добавить/удалить socket group, добавить/удалить/заменить активный камень, включение в FullDPS;
   - sets: создать/скопировать tree/item/skill set с ASCII-названием (для стадий прогрессии);
   - items: добавить джевел/кластер в сокет дерева.
   Все операции идут через штатные функции PoB, ошибки — фатальны, отчёт перечисляет фактические изменения.
3. Создание билда с нуля: `pob new --class X --ascendancy Y --level N --save-xml f.xml` (пустой валидный 3_30 XML).
4. Share code: `pob export-code <xml>` и импорт кода из файла/строки, с проверкой round-trip.
5. Завести git в корне с .gitignore (cache/, vendor/pob/runtime-бинарники, *.sqlite, backups/, node_modules/, research/ сырые выгрузки) — сначала покажи мне список того, что попадёт в первый коммит, и коммить только после моего ок.
6. Обновить ENVIRONMENT.md, BUILDING.md (раздел про --changes), устаревший HANDOFF.md (там "28/28 тестов"), статус в IMPROVEMENT-PLAN.md.

Готово, когда: все тесты зелёные, doctor --deep проходит, есть тест "собрать с нуля минимальный билд (класс, 10+ узлов, 1 группа камней) -> run -> export-code -> import -> те же числа".
```

## Промпт сессии 2 — граф дерева и игровые данные

```
Проект: локальное окружение для билдостроения PoE 1 3.30 (папка "<project>"). Прочитай AGENTS.md и poe-db/docs/IMPROVEMENT-PLAN.md (общие правила), выполни bootstrap. Твоя зона: новые модули в poe-db/scripts (например tree-graph.mjs, leveling.mjs, patch-changes.mjs, meta.mjs), новые таблицы/базы в poe-db/data, сборочные скрипты knowledge, минимальная регистрация команд в agent.mjs. Параллельно другая сессия правит pob.mjs/pob-worker.lua/doctor — их не трогай. PoB-движок не нужен.

Задачи:
1. Граф пассивного дерева 3.30 (из уже закреплённого GGG tree 3.30.0): команды `tree path --from <class|node> --to <node...>` (минимум очков, с учётом уже взятых узлов), `tree cost`, `tree near <node> --radius` (для джевелов/Timeless), `tree search --stat <text>`; поддержка masteries, cluster-сокетов, ascendancy отдельно. Выход совместим с будущей операцией allocate (список node id).
2. Данные прокачки: награды за квесты и продажа камней у NPC по актам и классам, доступность камней до 3 акта/до мапов; рецепты торговцев, важные для прокачки; leveling-уникальные предметы (флаг/список). Источник — RePoE/GGG/PoB-данные или Wiki с сохранением версии и происхождения. Команда `leveling gems --class X --act N`.
3. Изменения 3.29 -> 3.30 как данные: изменения камней, узлов, уникальных предметов, ascendancy (diff закреплённых снимков + официальные patch notes с источником). Команда `changes get <entity>`; карточка механики для проверки старых гайдов.
4. Мета: разобрать research/ (CSV лиг, verified-builds.json, FINDINGS.md) в отдельную базу с датой/лигой/источником; команды вроде `meta skill <name>`. Явно помечать 3.29/старые лиги и не выдавать за мету 3.30.
5. Timeless jewels: команда установки остальных баз есть (setup-pob --timeless) — только проверь и задокументируй, не скачивай без моего ок.

Сеть — только для явной загрузки источников, с кэшем и хешами по образцу fetch-knowledge.mjs. Обнови тесты, ENVIRONMENT.md, свой пункт в HANDOFF.md и статус в IMPROVEMENT-PLAN.md. Готово, когда: `tree path` от старта Witch до Elemental Equilibrium даёт корректный список узлов (проверка по графу), `leveling gems` для одного класса сверен с источником, тесты зелёные.
```

## Промпт сессии 3 — анализ, ранжирование и проверка модели

```
Проект: локальное окружение для билдостроения PoE 1 3.30 (папка "<project>"). Прочитай AGENTS.md, poe-db/docs/IMPROVEMENT-PLAN.md и HANDOFF.md, выполни bootstrap и doctor --deep. Предполагается, что сессия 1 (движок PoB + операции редактирования --changes) завершена; если нет — остановись и скажи мне. Используй команды сессии 2 (tree path, leveling, changes), если они уже есть. Твоя зона: новые модули analysis-*.mjs, сценарии боссов, evaluations/, регистрация в agent.mjs, навыки .agents/skills.

Задачи:
1. Node Power / веса статов: `analyze nodes <xml> --metric dps|ehp|maxhit --scenario sustained --radius N` — пакетный расчёт прироста по каждому доступному узлу (стоимость пути учитывать), с кэшем и одним calculation contract. `analyze stats <xml>` — прирост за +1% единиц ключевых статов (через custom_mods, помечая как эксперимент).
2. Ранжирование улучшений: `analyze upgrades <xml> --candidates file.json` — одиночные и пакетные изменения, итог по DPS/EHP/max hit/ресурсу/требованиям, с ценой из совпадающего снимка рынка (не смешивать при inconsistent_currency_conversion).
3. Проверка против контента: сценарии на основе boss_profiles (Uber Maven, Sirus, Shaper и т.п.: тип урона, пробитие, конфиг врага) -> `analyze survive <xml> --boss X` с max hit по типам и выводом «что убивает первым».
4. Оценка модели: инструмент прогона evaluations/cases.json (формат запроса, ожидаемые признаки ответа, ручная/полуавтоматическая оценка), добавь 5+ кейсов на новые функции (построение дерева, прокачка, устаревший гайд 3.29).
5. Эталонный сквозной пример: собрать с нуля через CLI один простой билд (выбери сам архетип с дешёвым стартом, пометь как synthetic/teaching), 2 стадии (campaign, early-maps) в отдельном build id (не main), пройти аудит и задокументировать как образец рабочего процесса.
6. Обновить навыки poe-build-design/poe-upgrade/poe-build-audit под новые команды (кратко, ссылками), BUILDING.md, HANDOFF.md, статус в IMPROVEMENT-PLAN.md.

Числовой эксперимент не является игровым тестом — так и пиши в отчётах. Готово, когда: analyze nodes на эталонном билде выдаёт осмысленный топ-10 за разумное время (замерь), survive работает минимум для 3 боссов, тесты зелёные.
```
