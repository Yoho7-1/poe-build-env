# Craft Lab: первый этап симулятора крафта

Локальный экспериментальный тренажёр для агента: **PoE 1 / 3.30 / Softcore**, без сервера, новых зависимостей и доступа к аккаунту. Агент получает предмет, список разрешённых действий с причинами отказа, остаток бюджета и проверку цели. Затем выбирает следующий шаг. Это практика через инструменты; веса самой нейросети этот код не обучает.

Работа изолирована в `poe-db/experiments/craft-lab`. Существующие CLI `agent.mjs`, SQLite, `builds/main`, lock-файл окружения, общая сводка и навыки не изменялись. Оригинальные данные читаются из закреплённого кэша; их SHA-256 проверяются при каждом запуске. Сохранение выполняется только по явному `--save` в новые файлы внутри `runs`, без перезаписи.

## Что выяснено при изучении проекта

Прочитаны `AGENTS.md`, краткая сводка `docs/HANDOFF.md`, карта `docs/ENVIRONMENT.md`, раздел крафта `docs/BUILDING.md`, карточки `affix-weight-context` и `item-level-equipment`, устройство CLI/SQLite и локальная реализация `ItemClass:GetModSpawnWeight` в PoB 2.68.1. Стартовый `doctor` прошёл; `builds/main` был revision 1, с неизвестными предпочтениями.

В knowledge есть 41 336 определений модов, 5 607 записей баз, 107 записей Essences, 445 справочных записей раздела Fossils и 782 определения bench recipes. Эти количества описывают справочник, а не число доступных в лиге вариантов. Отдельная база workbench содержит восемь условных крафтовых планов. Существующий `craft import` проверяет идентификаторы и часть условий рецепта; сам процесс и вероятности не моделирует.

Главный вывод: из списка весов нельзя сразу получить шанс готового предмета. Нужны контекст базы и item level, занятые prefix/suffix, конфликты mod groups, **первое** совпадение в упорядоченном `spawn_weights`, первое совпадение в `generation_weights`, теги от implicit и уже имеющихся explicit модов. Также нужны отдельные правила каждой операции. Новая реализация отделяет эти части и отказывается от неподдерживаемого контекста.

## Запуск

Команды ниже выполняются из корня проекта. Абсолютный путь к `cli.mjs` работает из любой папки; пути к входным JSON разрешаются относительно текущей папки.

```powershell
node poe-db/experiments/craft-lab/cli.mjs help
node poe-db/experiments/craft-lab/cli.mjs status
node poe-db/experiments/craft-lab/cli.mjs bases

# Пул для следующего Exalted Orb: limit не меняет общий знаменатель.
node poe-db/experiments/craft-lab/cli.mjs pool --base "Amber Amulet" --ilvl 86 --match IncreasedLife --limit 2

# Начальный предмет и законные действия. --save необязателен.
node poe-db/experiments/craft-lab/cli.mjs new --file poe-db/experiments/craft-lab/examples/amulet-start.json --save my-amulet-0.json

node poe-db/experiments/craft-lab/cli.mjs step --file poe-db/experiments/craft-lab/runs/my-amulet-0.json --action "Orb of Augmentation" --save my-amulet-1.json

node poe-db/experiments/craft-lab/cli.mjs pool --file poe-db/experiments/craft-lab/runs/my-amulet-1.json --action "Regal Orb" --limit 3

node poe-db/experiments/craft-lab/cli.mjs step --file poe-db/experiments/craft-lab/runs/my-amulet-1.json --action "Regal Orb" --save my-amulet-2.json

node poe-db/experiments/craft-lab/cli.mjs replay --file poe-db/experiments/craft-lab/runs/my-amulet-2.json

# Условный эксперимент с фиксированной последовательностью действий.
node poe-db/experiments/craft-lab/cli.mjs practice --file poe-db/experiments/craft-lab/examples/amulet-exercise.json --episodes 1000 --seed 42

node --test poe-db/experiments/craft-lab/test/engine.test.mjs
```

Имена сохранений должны быть простыми: lowercase ASCII, цифры, дефисы и `.json`. Повторное сохранение в существующий файл завершается ошибкой. Для следующего опыта выбирается новое имя. Для чтения состояния в `step` передавать именно сохранённый session JSON; полный stdout команды дополнительно содержит observation.

## Текущее покрытие

Базы: **Amber Amulet, Gold Ring, Leather Belt, Vaal Regalia, Rawhide Boots, Prophecy Wand**. Whitelist ограничивает первую версию проверенными по структуре обычными типами, а не заявляет доступность конкретного предмета или его начальных модов.

| Операция | Модель |
|---|---|
| Orb of Augmentation | Один новый мод на magic, максимум один prefix и один suffix |
| Regal Orb | Перевод magic в rare и добавление одного мода с лимитами rare |
| Exalted Orb | Один новый мод на rare, максимум три prefix и три suffix |
| Orb of Annulment | Удаление одного случайного explicit мода, rarity сохраняется |
| Orb of Scouring | Удаление explicit модов и перевод в normal |
| Divine Orb | Новые числовые rolls внутри тех же определений модов |

Неподдерживаемые поля сценария и действия вызывают ошибку. Influences, fracture, corruption, mirror, synthesised и другие особые состояния нельзя передать «дополнительным необрабатываемым флагом». Неудачный шаг не расходует валюту, не меняет предмет и не сдвигает RNG.

**Не реализованы:** Transmutation/Alteration/Alchemy/Chaos, Essences/Fossils, Harvest/Bestiary, bench/metamods, получение и изменение implicit, качество/Catalysts, sockets, импорт произвольного текста предмета, экспорт в PoB. После Scouring агент в этой версии не сможет снова сделать предмет magic: для этого нужна следующая стадия покрытия.

## Формат упражнения и цикл агента

`examples/amulet-start.json` содержит `base`, `item_level`, явную `rarity`, IDs начальных `mods`, `seed`, `budget` и `target`. Начальные numeric rolls создаются моделью. Это допущение о наличии предмета: стоимость получения этих модов не включена. Проверяются контекст базы, уровень, groups и ёмкость; начальное состояние не доказывает конкретную последовательность получения в игре.

Бюджет записывается в исходных единицах каждой валюты. `null` означает, что лимит не задан; в заданном объекте отсутствующая валюта имеет лимит 0. Цены и конфликтующие Chaos/Divine-курсы проекта не используются. Начальный предмет не записывается в профиль пользователя.

Цель может сочетать `all_mods`, `any_mods`, `rarity` и `stats: [{"id":"base_maximum_life","min":70}]`. Проверяются фактические rolls. Числа суммируются **только по explicit stats**: implicit Leather Belt, экипировка персонажа, требования ношения и эффекты билда в эту проверку не входят. `source_text` показывает диапазон из источника, а `stats[].value` — выпавшее значение. Полноценного форматтера строк предмета пока нет.

Цикл нейросети: `new` → чтение `observation` → выбор действия → `step` → проверка цели/расходов → следующий шаг или остановка. `step` и `replay` пересоздают исходный сценарий и проверяют всю цепочку по seed, включая rolls, состояние, расходы и историю. CLI не принимает отредактированный «удачный результат». Контракт включает код четырёх модулей и data lock; после изменения кода старый session не считается совместимым автоматически.

Программный интерфейс: `loadCatalog()` из `catalog.mjs`; `createSession`, `step`, `observe`, `pool`, `replay` из `engine.mjs`; `practice` из `practice.mjs`. Чистый `step` проверяет структуру и контракт; при загрузке внешнего session программный клиент сначала вызывает `replay`, как делает CLI. Входные объекты не изменяются.

`practice` многократно разыгрывает фиксированный список из `examples/amulet-exercise.json`, по умолчанию останавливаясь при достижении цели. Агент в интерактивном цикле может принимать разные решения после каждого результата; batch в первой версии адаптивную политику не оптимизирует. Вывод включает успехи, исчерпание плана, отказы, затраты по всем попыткам, mean/p50/p95 шагов и Wilson 95% interval для доли успеха. Это интервал выборки **внутри модели**, он не измеряет ошибку самой модели. Seed-последовательность детерминированная; seed доступен для отладки, поэтому это не защищённый экзамен для нейросети.

## Достоверность и источники

Статус во всех отчётах: `experimental`, `game_validated=false`, `acquisition_verified=false`. Есть программные тесты и закреплённые определения клиента; игровая проверка и независимое сопоставление вероятностей с актуальным внешним симулятором ещё не проведены.

Веса берутся из RePoE 3.30.0.4. Упорядоченная обработка веса и generation multiplier сверена с локальным PoB `ItemClass:GetModSpawnWeight`. Выбор нового мода пропорционально их произведению, равномерный Annulment и независимые равномерные целочисленные rolls являются **явными допущениями симуляционной модели**, не доказательством серверного алгоритма. Редкие серверные исключения, корреляции rolls и распределения количества модов пока не подтверждены. Число тегов не превращается в число независимых шансов.

- [RePoE — первичный проект поставщика выгрузки](https://github.com/repoe-fork/RePoE).
- [Закреплённый base_items.json](https://raw.githubusercontent.com/repoe-fork/repoe-fork.github.io/536caa88b673e232aa410cb47e20dc2d9ecd064e/data/base_items.json) и [mods.json](https://raw.githubusercontent.com/repoe-fork/repoe-fork.github.io/536caa88b673e232aa410cb47e20dc2d9ecd064e/data/mods.json): URL/SHA-256 сохранены в `data-lock.json`.
- [PoB: упорядоченные веса](https://github.com/PathOfBuildingCommunity/PathOfBuilding/blob/a41fec6c20f822a658ae5df1273e8c69d5969bac/src/Classes/Item.lua#L1722).
- [Craft of Exile: Basics](https://www.craftofexile.com/basics): справка о prefix/suffix и операциях; сайт при просмотре 23.11.2026 рекомендовал новую beta-версию. Данные/код CoE не копировались, его соответствие патчу 3.30 здесь не установлено.

## Следующий этап

1. Подтвердить распределения количества модов и порядок их генерации для Transmutation/Alteration/Alchemy/Chaos на 3.30; получить независимые контрольные случаи. Затем открыть цикл крафта с normal без допущения о начальном magic.
2. Добавить обычный bench с открытием рецепта, costs, groups, crafted limit и корректным удалением. Metamods и их взаимодействия проверять отдельно для каждого действия.
3. Добавлять Essences/Fossils/Harvest по одному семейству, с отдельной матрицей покрытия и отказами на неподдерживаемые комбинации. Наличие справочной записи не равно готовой механике.
4. Добавить адаптивные политики и сравнение стратегий по нескольким заранее отложенным наборам seed. Учитывать бюджет, неудачи и расходы получения начальной базы; не оценивать стратегию по единственному удачному прогону.
5. После проверки строк/rolls реализовать ASCII-экспорт предмета для `pob run --changes replace_items`. Сравнивать один baseline/сценарий и проверять требования, защиту и ресурсы билда. До этого числовая цель предмета не выдаётся за улучшение персонажа.
6. Подключить зрелый интерфейс к `agent.mjs` и навыкам отдельным изменением, когда общие файлы свободны. На этом этапе общие файлы соседней сессии не затрагивать.

`baseline.json` хранит контрольные суммы существовавших ключевых файлов; это свидетельство чтения, не резервная копия. `HANDOFF.md` в этой папке служит кратким входом для продолжения именно симулятора.
